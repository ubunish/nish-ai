# Nish AI Sync

`nish-ai` is the source of truth. `install.sh` symlinks every skill, command,
and agent into `~/.claude`, and injects the hook, permission, and statusline
configuration into `~/.claude/settings.json`. That contract has two leaks. This
skill catches an edit on either side of a leak and routes it back to the source
before it is lost.

## Two Loops

```
Loop A — harness wiring changed (hook / permission / statusline)
  NEVER hand-edit ~/.claude/settings.json
    → edit the generator in nish-ai/install.sh
    → ./install.sh        (re-inject, re-verify)

Loop B — a nish-ai-* skill / command / agent needs a change
  edit the repo source under nish-ai/<artifact>/   NEVER a ~/.claude/*.bak copy
    → ./install.sh        (relink, re-verify)
```

Why it matters:

- **Loop A.** The hook, permission, and statusline blocks in `settings.json` are
  generated by `install.sh`. A hand-edit there is overwritten the next time the
  install or uninstall cycle runs, so the change never sticks. The durable fix
  lives in `install.sh`.
- **Loop B.** Skills, commands, and agents install as symlinks. Editing through
  a live symlink reaches the repo, which is fine. But when `install.sh` hits a
  name conflict it moves the old target aside to a `.bak` backup; an edit made
  to that backup is local-only and clobbered on the next run. `./install.sh
  status` shows which targets are linked versus in conflict.

## Triggers

This skill auto-loads from its description when any of these appear:

- An edit under `~/.claude/skills/nish-ai-*`, `~/.claude/commands/`, or
  `~/.claude/agents/`.
- A hand-edit of `~/.claude/settings.json` touching the nish-ai hooks,
  permission allowlist, or statusline.
- User intent to change any `nish-ai-*` skill, command, agent, or the
  install and hook behavior.

## What To Do

1. **Locate the source.** The repo root is `~/ubunish/nish-ai`. Content edits
   belong in the artifact dir — `nish-ai-<skill>/`, `commands/`, or `agents/`.
   Harness wiring belongs in `install.sh`.
2. **Apply the edit to the repo source**, never to `settings.json` or a `.bak`.
3. **Relink.** Run `./install.sh` from the repo root, then `./install.sh status`
   to confirm every artifact is linked (not in conflict) and the hook,
   permission, and statusline blocks are present.
4. **Test if install logic or a hook script changed.** Run `uv run pytest`.

## Source-of-Truth Discipline

- Never edit `~/.claude/settings.json` directly as the fix. It is generated; the
  fix lives in `install.sh`.
- Never edit a `~/.claude/*.bak` backup. That is a discarded copy.
- A symlinked skill edit is live immediately; a `settings.json` block needs
  `./install.sh` to refresh. When in doubt, re-run `install.sh`.
- One change, one place: the repo. Everything in `~/.claude` is regenerated
  from it.
